## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

```text
kern_init → idt_init 写入 stvec → clock_init 设置首个时钟事件 → intr_enable
Trap 发生 → __alltraps → SAVE_ALL → trap → trap_dispatch
  → interrupt_handler 或 exception_handler
  → __trapret → RESTORE_ALL → sret
```

初始化决定 CPU 到哪里处理 Trap。事件发生后，硬件更新 `sepc`、`scause` 等控制寄存器，汇编把通用寄存器和相关控制寄存器保存到栈上。C 根据原因处理事件，再由汇编恢复现场。断点和非法指令处理修改栈帧里的 `epc`，这个修改在返回前通过 `RESTORE_ALL` 写回 `sepc`。

### 2.2 功能的逐步实现

先对齐 `SAVE_ALL`、`struct trapframe` 和恢复顺序，建立从汇编到 C 再返回的路径。然后接通时钟分支和异常分支，最后用持续输出、异常返回以及配套测试分别验证。初始化沿用工程的物理页管理逻辑，启动页表和 QEMU 加载参数做了本机运行适配。

## 四、实验内容与实现

### 功能模块：Trap 上下文恢复与 Trap 入口

#### 模块功能描述

[kern/trap/trapentry.S](kern/trap/trapentry.S) 的 `__alltraps` 调用框架已有 `SAVE_ALL` 后，补上 `mv a0, sp` 和 `jal trap`。此时 `sp` 指向 Trap frame，`a0` 按调用约定传递第一个参数。C 返回后执行 `__trapret`。

[kern/trap/trap.h](kern/trap/trap.h) 的栈帧是 32 个通用寄存器槽位加 4 个 CSR 槽位，共 288 字节。`RESTORE_ALL` 从第 32、33 号槽写回 `sstatus` 和 `sepc`，再恢复通用寄存器。旧 `sp` 在第 2 号槽，必须最后加载，因为此前读取都以当前 `sp` 为基址。`scause` 和 `sbadaddr` 提供本次 Trap 的诊断信息，返回不要求写回它们。`sret` 按 `sepc` 和 `sstatus` 的状态继续执行，本实验中由内核触发的 Trap 返回 S 模式。

#### 最终提示词

见 [prompt.md](prompt.md) 第 1 节。spec 先规定输入是有效栈帧，再规定恢复后的寄存器与返回状态。提示词把槽位、`a0` 传参、`sp` 最后恢复和保留框架接口列为显式约束，验收检查断点返回后的寄存器值。

#### 实现迭代过程

初次用优化构建观察处理函数时，内联使断点出现多个位置，函数返回不便观察。调试构建改用 `DEBUG=1` 关闭优化，常规运行和评分仍用相应的正常构建参数。配套评分的 Trap 入口、寄存器恢复与断点 EPC 项通过，得分 35/35。

### 功能模块：中断与异常处理

#### 模块功能描述

[kern/trap/trap.c](kern/trap/trap.c) 中，框架已有的 `trap_dispatch()` 按原因值最高位分流。`interrupt_handler()` 去掉中断标志位后识别中断类型。S 模式时钟分支先调用 `clock_set_next_event()`，再执行 `ticks++`。每累计 100 次调用 `print_ticks()`，输出次数达到当前实现的 `SHUTDOWN_AFTER=10` 后通过 SBI 关机。其他已识别中断输出类型，未知中断打印 Trap frame。

`exception_handler()` 对断点和非法指令输出异常地址，并根据首个半字的最低两位为本实验的 16 位、32 位指令选择 2 或 4 字节偏移。这样返回时能跳过触发指令。其他异常打印 Trap frame 供排查。时钟中断不修改 `epc`，从保存的位置继续执行。

#### 最终提示词

见 [prompt.md](prompt.md) 第 2 节。spec 分别描述时钟、其他中断、断点和非法指令、其他异常四种路径，并明确每种路径的计数、输出和 `epc` 行为。提示词规定重设时钟的动作必须发生在每次时钟中断中，关机阈值按输出次数统计。

#### 实现迭代过程

异常演示首次把 `DEFS` 写成 `DEF`，构建没有启用演示宏。改正拼写后直接运行仍复用了旧产物。先 `make clean`，再用正确宏重新编译，终端出现三组异常提示及 `returned`。配套评分中，非法指令 EPC 更新和返回得 25/25，持续时钟中断得 40/40。

## 六、实验总结与收获

### 对操作系统的理解

| 实验知识点 | 对应的操作系统原理及区别 |
|---|---|
| Trap frame 和返回指令 | 对应中断现场保护。本实验把现场放在当前栈上，处理完回到原执行流。进程切换还要维护独立的任务状态，并选择下一个可运行任务。 |
| `scause` 分流及 `epc` 更新 | 对应同步异常与异步中断。时钟中断返回原执行位置，而实验中的断点与非法指令按长度跳过。可修复的缺页通常在补好映射后重试故障指令。 |
| 持续时钟中断 | 给周期性内核工作提供时间基础。本实验用它计数与关机，实际内核可以进一步用它驱动时间片和定时任务。 |
| `local_intr_save` / `local_intr_restore` | 保证修改页分配器数据时，本核中断不会在临界区内打断执行。多核并发访问同一数据还需要适当的锁。 |

本实验没有实现进程调度、用户态系统调用分发、缺页恢复和多核同步。这些机制可以复用 Trap 入口或中断机制，但各自还需要额外的策略和数据结构。

### AI 协作开发的经验

给出实际函数签名和栈帧布局后，再说明每个分支的前置条件与预期结果。检查汇编时，把保存顺序与恢复顺序逐槽对照。检查中断时，分别验证下一次事件是否设置、返回地址是否正确、寄存器是否恢复。切换演示宏时清理构建产物，并用实际输出确认运行的是目标版本。
